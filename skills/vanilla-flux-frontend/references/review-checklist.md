# 审查清单

自查或交给独立 reviewer（只读）时使用。输出分 must-fix / should-fix / follow-up，每条给 文件:行号、触发步骤、建议修法。改造类任务要对照旧代码（`git show <base>:<path>`）找用户可见行为的回归。

## 数据流与模块

- [ ] 共享数据是否只经 store setter 修改？有没有绕过 setter 直接改对象属性后忘了发事件？
- [ ] 模块之间是否还有互相调用渲染函数、循环依赖？
- [ ] `subscribe` / `on` 是否只在 bind 里注册一次？
- [ ] 初始化顺序：bind 先于加载数据时，渲染函数是否处理了"主对象未加载"？刷新时恢复的页签 / 视图会不会在数据到达前渲染而报错？
- [ ] 切换主对象：后台任务断开、选择清空、筛选重置是否与旧行为一致？晚到的旧请求结果会不会覆盖新对象？
- [ ] 改造前后对照：旧界面上显示的字段、按钮、面板是否都还在（可能被移进"显示"菜单，但默认要显示）？有没有为了"清爽"悄悄删掉信息？
- [ ] 偏好存储：localStorage 的 key 带版本号？读取是否校验并丢弃非法值？
- [ ] 失败路径：请求被拒时，用户输入（表单、编辑中的文本）和已有日志是否保留？弹窗是否只在成功后关闭？

## 安全

- [ ] 所有插值都经 `html` 转义；`raw()` 只用于常量标记。
- [ ] `${n && …}`（n 可能为 0）与布尔属性值。
- [ ] 鉴权前加载的页面（登录页）引用的脚本、样式及其 import 是否都在服务端放行名单内？否则表单会原生提交、把凭证带进 URL。
- [ ] 下载、预览的 URL 与文件名来自可信字段并已转义。

## 类型

- [ ] strict checkJs 通过；`/** @type */` 强转、`any` 有没有掩盖真实的空值？
- [ ] 前端类型是否引用后端定义，而不是手抄一份？

## 可访问性

- [ ] 所有可点击元素都能用键盘到达（不是 div / img 加 click）；图标按钮有可读名称。
- [ ] 焦点环在主按钮、选中项、自定义控件上都可见。
- [ ] 状态不只靠颜色；小字对比度达 AA。
- [ ] 全局快捷键：遇到输入框、修饰键（Ctrl/⌘/Alt）不拦截；叠在另一个对话框上的弹层不把按键漏给下层（内层处理 Esc 后 `preventDefault()`，外层先检查 `e.defaultPrevented`）。
- [ ] toast 在模态对话框打开时可见（popover / 顶层）。

## 样式与布局

- [ ] 有没有残留的裸值、写死的浅色（暗色模式下刺眼）？
- [ ] JS 生成的 class 在新 CSS 里都有规则；被删的选择器没有标记还在用。
- [ ] 改按钮文字的代码会不会把图标一起清掉？
- [ ] 断点下：栏内容是否可达（overflow 截断）、sticky 元素是否被顶栏盖住、徽标是否被挤截断。
- [ ] 预览 / 画布的尺寸计算是否扣除了 padding。
- [ ] 下拉菜单、气泡在栏边缘打开时是否被 `overflow` 裁切？
- [ ] 时间显示是否都经格式化模块、用约定时区？有没有残留 `toLocaleString()` / `getHours()`？

## 测试与交付

- [ ] 新纯逻辑有单元测试；新交互有 e2e；每个提交单独可通过。
- [ ] 截图检查过亮 / 暗、宽 / 窄。
- [ ] 项目文档写明了约定（store、模板、token、测试分层），AGENTS.md / CLAUDE.md 有入口。
